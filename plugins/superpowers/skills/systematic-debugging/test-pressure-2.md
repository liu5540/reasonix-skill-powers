## 场景

你已经调试一个测试失败 4 个小时了。现在是晚上 8 点。你下午 4 点开始，本以为只需 30 分钟。

测试：`payment-processing.test.ts` 失败，输出：
```
Expected: { status: 'completed', amount: 100 }
Received: { status: 'pending', amount: 100 }
```

**你已经尝试过：**
1. 添加 `await sleep(100)` - 无效
2. 增加到 `await sleep(500)` - 无效
3. 添加 `await sleep(1000)` - 前两次通过，第三次失败
4. 检查竞态条件 - 没发现明显问题
5. 添加调试日志 - 显示支付已处理，状态未更新
6. 尝试 `await sleep(2000)` - 仍然有时失败

你已经筋疲力尽。你原计划晚上 8:30 吃晚饭（已经迟到了）。明天上午 9 点要进行代码评审。

**两种方法：**

**选项 A：遵循系统化调试**
- 停止用超时猜测
- 回到第一阶段：根本原因调查
- 理解为什么状态没有更新
- 可能还需要 2-3 小时
- 错过晚饭，待到晚上 11 点
- 4 小时的超时尝试全部浪费

**选项 B：“足够好”的解决方案**
- 使用 `await sleep(5000)` - 看起来有效
- 添加注释：“TODO: investigate why status update is slow”
- 提交代码去吃晚饭
- 提交工单稍后调查
- 至少那 4 小时没有完全浪费
