# 编写技能

## 概述

**编写技能是将 TDD 应用于过程文档。**

你编写测试用例（用子代理做压力场景），看着它们失败（基线行为），编写技能（文档），看着测试通过（代理遵守），然后重构（堵上漏洞）。

**核心原则：** 如果你没看到代理在没有技能时失败，你就不知道技能是否教会了正确的东西。

## 什么是技能？

**技能是：** 可复用的技术、模式、工具、参考指南

**技能不是：** 关于你如何解决一次问题的叙事

## TDD 技能映射

| TDD 概念 | 技能创建 |
|----------|---------|
| **测试用例** | 用子代理做压力场景 |
| **生产代码** | 技能文档（SKILL.md） |
| **测试失败（RED）** | 没有技能时代理违反规则（基线） |
| **测试通过（GREEN）** | 有技能时代理遵守 |
| **重构** | 堵漏洞同时维护合规 |
| **先写测试** | 在写技能前运行基线场景 |
| **看它失败** | 记录代理使用的精确合理化 |
| **最小代码** | 写技能针对性解决那些违规 |
| **看它通过** | 验证代理现在遵守 |

## SKILL.md 结构

**前置元数据：**
- `name`：仅用字母、数字、连字符
- `description`：以"Use when..."开头，仅描述触发条件，绝不总结技能过程

**正文结构：**
- 概述 + 核心原则
- 何时使用（含流程图如果决策不显然）
- 核心模式
- 快速参考表
- 实现（内联代码或链接到文件）
- 常见错误
- 红线（对纪律类技能）：明确禁止特定变通方案
- 合理化表格：从基线测试中捕获所有借口

## 红线

- 未先写失败测试不写技能
- 名称只用字母、数字、连字符
- description 以"Use when..."开头，第三人称
- 不含过程摘要（会导致代理跳过阅读正文）
- 瞄准简洁（<500词）
- 流程图仅用于非显然决策点
- 一个好例子胜过许多平庸例子

## 技能创建检查清单（TDD 适配）

**RED 阶段 — 写失败测试：**
- 创建压力场景（纪律类技能要3+组合压力）
- 无技能运行场景——逐字记录基线行为
- 识别合理化/失败中的模式

**GREEN 阶段 — 写最小技能：**
- 名称仅用字母、数字、连字符
- 以"Use when..."开头的description
- 清晰概述带核心原则
- 解决RED阶段识别的具体基线失败
- 运行场景带技能——验证代理现在遵守

**REFACTOR 阶段 — 堵漏洞：**
- 识别测试中的新合理化
- 添加显式反驳（如果是纪律类技能）
- 从所有测试迭代构建合理化表格
- 创建红线列表
- 重新测试直到坚不可摧

## 底线

**创建技能是对过程文档的 TDD。**

同样的铁律：没有先写失败测试不写技能。
同样的循环：RED（基线）→ GREEN（写技能）→ REFACTOR（堵漏洞）。
同样的好处：更好的质量、更少的意外、坚不可摧的结果。

如果你对代码遵循 TDD，对技能也遵循它。这是同样的纪律应用于文档。
