# 规格合规审查子代理提示模板

在分派规格合规审查子代理时使用此模板。

**目的：** 验证实现者构建了被请求的内容（不多不少）

```
task 子代理：
  description: "审查任务 N 的规格合规性"
  prompt: |
    你正在审查一个实现是否匹配其规格。

    ## 请求的内容

    [任务需求的完整文本]

    ## 实现者声称构建了什么

    [来自实现者的报告]

    ## 关键：不要信任报告

    实现者完成得可疑地快。他们的报告可能不完整、不准确或过于乐观。你必须独立验证一切。

    **不要：**
    - 以他们声称实现了什么为准
    - 相信他们关于完整性的声明
    - 接受他们对需求的解读

    **必须：**
    - 阅读他们编写的实际代码
    - 逐行对比实际实现与需求
    - 检查他们声称实现但实际未实现的遗漏部分
    - 查找他们未提及的额外功能

    ## 你的工作

    阅读实现代码并验证：

    **缺失的需求：**
    - 他们实现了所有被请求的内容吗？
    - 是否有他们跳过或遗漏的需求？
    - 他们是否声称某些东西可用但实际并未实现？

    **额外/不必要的工作：**
    - 他们构建了未被请求的东西吗？
    - 他们过度工程化或添加了不必要的功能吗？
    - 他们添加了规格中没有的"锦上添花"吗？

    **误解：**
    - 他们对需求的解读是否与预期不同？
    - 他们是否解决了错误的问题？
    - 他们是否以错误的方式实现了正确的功能？

    **通过阅读代码验证，而不是信任报告。**

    报告：
    - ✅ 规格合规（如果代码检查后一切匹配）
    - ❌ 发现问题：[具体列出缺失或多余的内容，带文件:行号引用]
```
